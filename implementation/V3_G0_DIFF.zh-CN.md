## 3. 需要确认的重要新规则（建议整组确认）

| ID | 建议采用的确定规则 | 与 FE-1 / 设计包的关系 |
|---|---|---|
| V3-D01 | 一个现有群就是一个团队任务空间；当前成员可看该群现有任务的当前摘要、描述与检查项；历史评论/活动仅限本次加入后，来源消息始终按 since_join | 新成员摘要可见是新增产品规则，不能据此扩大旧聊天、附件、搜索或引用权限 |
| V3-D02 | 普通成员默认可建本人负责或待认领任务；只允许群主/管理员指派给其他成员；单负责人；群禁言同时限制任务写入 | 共用群角色与成员事务，不新增平行成员系统 |
| V3-D03 | 个人任务正常产品接口仅本人可读写；超管不提供全站私人待办常规列表/搜索/导出。仅在本人举报/报障提供的具体对象和最小必要内容上执行受审计处理 | 保留 FE-1 已批准的超管私聊、群聊及附件审阅。已发送的个人静态副本属于聊天消息，仍适用该审阅权；超管不能从副本追溯原私人任务。这一条明确解决 V3 文档对副本运营访问与 FE-1 的冲突 |
| V3-D04 | 个人分享是确认后的静态副本；群实时卡片限本群或有当前访问权的同群好友私聊；个人复制到群创建新实体且告知当前/未来成员可见 | 分享不自动授权；退群即停止动态卡片解析，静态副本独立按聊天保留 |
| V3-D05 | 离线任务操作只存账号隔离草稿；恢复网络后重新检查身份、权限、最新版本，再由本人确认提交 | 不自动重放改派、删除、认领或分享；与聊天待发队列保持不同提交行为 |
| V3-D06 | 软删除回收期 30 天；群解散后任务冻结并进入同等保留/清理周期；个人注销冷静期内冻结，到期清除私人任务；未结举报阻止硬清理，结案后再保留 30 天，审计仍为 180 天 | 共享聊天和静态副本继续遵循 FE-1。缩短保留期先预览影响，测试清理仅针对隔离数据 |

移动端建议使用「消息、待办、通知、更多」四项底栏；联系人、本机待发、文件、设置放入「更多」，仍保留待发失败提示和原功能。桌面保留浅灰浅蓝聊天主体并增加待办入口。正式断点以 320–1920px 的内容与操作可达性测试统一，原型断点不作为修改稳定布局的硬要求。

P1 若获确认：个人清单/标签只组织本人任务；收藏/关注不扩权；运营扩展沿用上表私人任务边界；站内提醒使用任务时区和持久 jobs，不承诺浏览器关闭时系统推送。

## 4. 实际代码接缝

| 已有路径/机制 | 拟新增/扩展 |
|---|---|
| `src/tongpin/migrations/` | 增量 todo_tasks/check_items/activities/message_cards/mutation_keys/group_settings；P1 独立表及索引，保持关闭开关可回退 |
| `src/tongpin/domain/access.py`、M5 群服务 | 复用本次成员期、角色、禁言与解散权威；成员退出同事务取消未完成任务负责人；来源单独鉴权 |
| `src/tongpin/domain/chat.py`、`contracts/chat.py` | 普通消息附受控关系行，中性兼容正文；服务器建立任务卡片，客户端不能任意注入任务 ID；读取逐卡授权 |
| `domain/events.py`、`jobs/repository.py` | 引用型任务事件、同事务通知/持久工作；不在广播 payload 保存任务正文 |
| `transports/http/`、`contracts/` | 适配现有 `/api/v1` 与错误包络的任务 API；If-Match/ETag、先鉴权后冲突判断、持久命令 key |
| `apps/web/src/lib/api.ts`、`chat-client.ts` | 单 Cookie/CSRF 客户端、单 Socket/游标；未知事件安全推进；账号隔离任务实体状态与冲突/失权清理 |
| `outbox.ts` / 离线恢复页面 | 独立任务草稿存储与复核；退出说明同时统计聊天和任务草稿；不自动发任务管理命令 |
| ChatWorkspace / Navigation / MessageTimeline / Notifications | 新待办页面、详情、表单、分享/复制预览、消息转待办、三种卡片/墓碑、基础通知；详情遮挡时暂停聊天自动已读 |
| M7-Admin / M8 / M9 | 治理适配、V2+V3 联动回归、三平台测试、升级/功能关闭回退演练、交付手册 |

迁移、接口、目录命名可按实际工程细化，不为匹配参考包重命名已稳定的 V2 公共接口。P0/P1 用服务器权威功能开关；关闭后任务 API 明确不可用，登录、聊天、群和中性卡片回退保持可用，数据表不被自动删除。
